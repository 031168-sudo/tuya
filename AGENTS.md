# AGENTS.md — «Мой дом»

Правила и техническая память проекта. Карточка для памяти проектов —
`031168-sudo/memory`, `memory/apps/moy-dom.md`; техника живёт здесь.

## Что это

Android-приложение (Kotlin + Jetpack Compose) для управления домом из одного
места: облако Tuya (или LAN), Rubetek, Xiaomi (Mi Home) и учётный счётчик
НАРТИС по Bluetooth. Владелец — Андрей, общение по-русски, простыми словами.
Иконка — детский пастельный домик с солнцем.

Главная цель — отапливать дом электричеством с минимальной стоимостью,
опираясь на датчики, тарифы и прогноз погоды.

## Сборка и доставка

- Работа и сборка — только через GitHub.
- Пуш в `main` → GitHub Actions запускает unit-тесты, собирает APK и
  публикует релиз `build-N` с файлом `MoyDom-N.apk`
  (`versionCode` = номер прогона).
- Прямая ссылка:
  `https://github.com/031168-sudo/tuya/releases/download/build-N/MoyDom-N.apk`
  (последний релиз — `https://github.com/031168-sudo/tuya/releases/latest`).
- Ручной запуск: GitHub → Actions → Build APK → Run workflow.
- Готовый APK — только из GitHub Releases.

  `EnergyScreen`, `TariffsScreen`, `NartisScreen`, `SensorScreen`,
  `CategoriesScreen`, `SetupScreen`, `LocalScreen`, `LogScreen`,
  `Palette`/`Theme`, `DeviceIcons`, `CommandsUi`, `BackupUi`.
- DLMS-библиотека MIT — в исходниках (`com/pivotaccess/dlmscosem`), см.
  `THIRD_PARTY.md`.

## Аккаунты и устройства

- Основной аккаунт — приложение **Tuya Smart** (не Smart Life). Есть
  разработческий аккаунт на `platform.tuya.com` (Access ID/Secret вводятся
  на телефоне, дата-центр Central Europe).
- Три счётчика «智美WiFi开关电表» — по ним нужна полная история потребления.
- Умный дом: тёплые полы и потолочные ИК-обогреватели на Tuya-термостатах,
  уличный датчик «Датчик T & H», Rubetek (розетки/реле, через облако),
  Xiaomi: обогреватель «Mi S» (`zhimi.heater.mc2`, описание встроено) и
  кухонный обогреватель — он в зоне отопления, но план управляет им только
  вкл/выкл (уставка 22° на самом приборе, таймеры в Mi Home).
- Новые устройства просто появляются в списке (состояние + управление);
  в логику отопления и тарифов их не затягивать без просьбы.

## Отопление, «Дежурство», «Тепло»

- «Отопление»: план нагрева тёплых полов на сутки по зонным тарифам Т1–Т3
  и прогнозу; для комнаты — окна комфорта, дежурная температура, допустимая
  просадка в пик. «Автопилот» пишет план в облачные таймеры Tuya
  (`/v1.0/devices/{id}/timers`, своя категория `moydomheat`), ночная задача
  пересчитывает по свежему прогнозу.
- «Дежурство» (сборка 170) считает план **от факта**: стартует с реальной
  температуры зоны (свежей, не старше 2 часов), а не с нижней границы
  комфорта; планирует 24 часа от текущего часа; первые шаги догрева не
  считаются «нехваткой мощности». На графике — оранжевая линия фактической
  температуры и подписи «сейчас / +6 / +12 / +18 / +24».
- Таймеры: если первое событие плана уже прошло, вкл/выкл сдвигается на
  следующую минуту (иначе модуль сработал бы завтра). Сравнение «план
  изменился» этот сдвиг не учитывает.
- Подбор параметров (`ZoneLearner`/`ThermalFit`) применяется только при
  полном и надёжном результате: нужны и нагрев, и остывание, без ошибок;
  остывание меньше 0,5 %/ч не применяется (шум).
- Одноразовая миграция: подозрительное остывание 0,3 %/ч заменяется на
  типовое 3 %/ч (сборка 170 меняла только в памяти — в 171 сохраняет,
  флаг `loss_fix_home_v2` / `loss_fix_duty_v2`).
- «Тепло» (сборка 167) — отдельный экран, кнопка в шапке «Отопления»/
  «Дежурства»: план дома с закраской по теплосохранности, рейтинг зон,
  остывание %/ч, нагрев °/ч, время 22°→18° при −10°, кривые остывания.

## Счётчик НАРТИС (Bluetooth, DLMS/СПОДЭС)

Рабочие параметры — выстраданы, не менять наугад:

- Короткий адрес счётчика **1**, клиент **32**, пароль чтения **00000001**.
  Пароль `00002080` счётчик отвергает (`AARE rejected`). PIN сопряжения
  обычно `123456`.
- Обмен: BLE через Nordic UART (NUS) + локальный TCP-мост (`NusBridge`).
  Кадр уходит одним пакетом (MTU 247, согласование MTU перед обменом);
  дробление по 20 Б ломало HDLC.
- Перед чтением закрыть «Нартис Пульт»: счётчик пускает одно подключение.
- Серийный номер вводится в настройках (например `023260164390`), поиск
  идёт только по нему. Счётчик виден в общем списке как «Счётчик НАРТИС»,
  категория/комната назначаются через ⋮.
- Читаются: общий расход и Т1–Т3, мощность, напряжение, ток по фазам A/B/C,
  частота. Показания попадают в историю: авточтение раз в 30 минут при
  открытом приложении + ночной `NartisReadWorker` около 3:00 (если счётчик
  не виден — пропуск).
- В шапке экрана — «Копировать»/«Поделиться» журналом (до 1000 строк).
- Известный дефект: библиотека спотыкается о лишний байт `7E` в конце
  кадра — пока просто логируем ошибку.
- Полезные источники при разборе: Gurux-форум (реальный кадр НАРТИС-И100,
  адрес `02 23`), `latonita/esphome-dlms-cosem` и `...-ble`, руководство
  НАРТИС-И300 (пароль на чтение общий, на конфигурирование индивидуальный,
  после 5 неверных попыток запись блокируется на сутки).
- История поиска (сборки 154–159): DM на неверный кадр → правка кадра под
  НАРТИС → адрес 1/17 → отправка одним пакетом → UA и подключение → подбор
  пароля и клиента → успех на клиенте 32 с паролем `00000001`.

## Погода

- Основной источник — **Gismeteo** (`services.gismeteo.ru`): город по
  координатам, прогноз на сегодня/завтра раз в 3 часа, раскладывается по
  часам линейно. `wttr.in` — запасной.
- Open-Meteo убран 16.11.2026 (с мобильной сети не открывался).
- Прогноз кэшируется на 30 минут; при ошибке — последний сохранённый.
  Погода «сейчас» на «Карте» — тоже Gismeteo (факт + мин/макс на сегодня).

## Правила работы

- Обсуждаем до слова «делай»; мелкие однозначные просьбы — сразу.
- Правки копим в `BACKLOG.md`, делаем пачкой по указанию.
- После правки — push в GitHub; сборку и тесты выполняет Actions.
- Готовый APK — из GitHub Releases; ссылку давать на релиз.
- Новые версии ставятся поверх старых (общий debug-ключ `app/debug.keystore`).
- Любое удаление в приложении сначала спрашивает «Вы уверены, что хотите
  удалить?».
- Ключи Tuya/Rubetek/Xiaomi — только на телефоне, в репозиторий не попадают.
